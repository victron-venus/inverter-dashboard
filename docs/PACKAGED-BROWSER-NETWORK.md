# Packaged browser qualification network

Application and synthetic MQTT/IGW/HA containers attach only to a UUID-owned Docker bridge created with `--internal`. Both network and each container carry the same `dashboard.packaged-qa` ownership label. No Docker ports are published and no second network or gateway is added.

Docker cannot publish a port for a container that has only internal networks: port publishing requires a default-gateway network. A Moby maintainer [explains this behavior and native Linux host access](https://github.com/moby/moby/discussions/53256). The original candidate lanes failed before any browser/runtime qualification because the requested loopback ports were not published. Empty fixture logs do not establish any product defect.

The runner therefore validates the exact running container and reciprocal network endpoint: UUID names/labels, full container/network/endpoint IDs, sole network membership, RFC1918 IPv4 subnet, fixed fixture 8090 or application 8080, and no host port bindings. A host TCP relay binds an ephemeral port on 127.0.0.1 and forwards only to that validated endpoint. Browser URLs and existing HTTP/WebSocket origin/auth tests remain loopback-only. This path requires a native Linux Docker host; Docker Desktop is not supported by this qualification runner.

The relay supports HTTP and WebSocket byte streams without interpreting requests or selecting destinations from client data. Each relay permits 32 active connections, uses 64KiB buffers per direction, connects within 5seconds, and bounds idle/lifetime to 60/300seconds. All listener/connection workers are stopped before container cleanup. Cleanup failure fails the job, and Docker teardown is still attempted independently. Diagnostics contain selected boolean/exit state and validated network identity; environment, credentials, mount data and raw health logs are excluded.

Ordinary PR CI includes a mandatory `Internal Docker network topology` job on explicit `ubuntu-24.04`. It runs fixed synthetic servers from the existing digest-pinned Python image, checks both 8090/8080 routes through the production validator/relay, and tears down every owned resource. It builds no application and is topology evidence only. Local tests exercise real loopback HTTP, WebSocket upgrade, bounded large duplex traffic, half-close, connection limits, timeouts and teardown plus adversarial metadata. Actual OCI product qualification still requires the normal candidate release job and its complete browser evidence; no local topology result can replace it.

The synthetic TLS fixture runs as the native Linux runner's positive numeric UID:GID, matching the owner of its generated private key. Startup refuses a linked, foreign-owned or non-0600 key. The read-only bind mount, dropped capabilities and no-new-privileges settings remain in force; no DAC capability or TLS verification bypass is added. Only the public CA certificate is 0644 so packaged backend users can read it.

The ordinary hosted topology regression starts the actual packaged fixture using the same launch helper and generated 0600 key. It checks HTTP startup, a CA- and hostname-verified HTTPS snapshot, rejection of a wrong hostname and untrusted CA, and sanitized process UID/GID, key ownership/mode and zero effective capabilities. These observations qualify the fixture infrastructure; the six real application/engine/transport rows still qualify the packaged candidate separately.
